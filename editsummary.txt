## 2026-11-23 - Foundry bridge: client, bookkeeping and 5-minute pass (medications only, off unless FOUNDRY_WRITES=1)
- server/services/foundryService.js (new): Foundry Ontology API v2 client. Personal token from FOUNDRY_TOKEN, plus FOUNDRY_URL and FOUNDRY_ONTOLOGY_RID. applyAction(apiName, parameters), getActionType (cached; used to find the object parameter of delete actions instead of guessing its id), listLinkedObjects (for array-item deletes later). Errors carry only the HTTP status and Foundry error name, never parameter values or the token. 20 s timeout.
- server/services/foundryBridge.js (new): per-model registry (only Medication -> MmcMedication, actions save-mmc-medication and delete-mmc-medication, exactly as listed in the ontology), allow-list mapping for the 41 MmcMedication properties, mmcKey rules (Mongo _id, or <patientKey>:<provider>:MedicationRequest/<resourceId> for Epic, kept once sent), test-member gate (User.foundryTestMember; Epic records only from the fhir.epic.com sandbox; payer FHIR not sent; others skipped, not failed), send-after-save queue (one at a time, never throws), delete queue processing, runPass().
- server/models/plugins/foundryTracked.js (new): adds foundryKey, foundryChangedAt, foundryRecordedAt, foundryRecordError (index on foundryRecordedAt). Marks a record changed on save, updateOne, updateMany and findOneAndUpdate; strips foundry* keys from incoming updates and undoes them on save; reads foundryKey before deleteOne/deleteMany/findOneAndDelete and queues the delete, so the family-member, account and admin cascades are covered. Bridge bookkeeping writes go through the native driver so they do not count as changes.
- server/models/FoundryDeleteQueue.js (new): pending deletes, keys only (objectType, primaryKey, attempts, lastError).
- server/models/Medication.js: foundryTracked plugin. server/models/User.js: foundryTestMember (Boolean, default false; not in the profile allow-list, set by an admin in the database).
- server/server.js: 5-minute cron (*/5) next to the reminder job, scheduled only when FOUNDRY_WRITES=1: delete queue first, then pending medications of test members, never-failed and oldest first, 200 per pass (this also backfills records saved before the bridge).
- server/.env.example (new): every server env name with no values, including FOUNDRY_WRITES, FOUNDRY_URL, FOUNDRY_TOKEN, FOUNDRY_ONTOLOGY_RID. README.md env list and CLAUDE.md (Foundry line, cron list, models table) updated; docs/foundry-bridge.md status line updated.
- No Foundry spec files. Checked with node -c on every changed server file and a local run against in-memory MongoDB and a mock Foundry server (flag off: no calls; test member sent, other member not; client cannot set foundry* fields; 401 gives foundryRecordError and the pass resends; backfill of a legacy record; Epic key only with a sandbox connection; deletes sent and queued on failure).
